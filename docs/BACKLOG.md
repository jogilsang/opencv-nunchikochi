# 작업 큐 (탭별) — 지휘자가 관리, 탭이 대기가 되면 자기 몫의 다음 미완료 항목을 지시

표기: `[ ]` 대기 · `[~]` 진행 · `[x]` 지휘자 검증 완료. 의존은 "←". 시간은 에이전트 작업 시간 추정.
핵심 경로: V1 → C1(스텁 연결) → 통합(10/23) → V3·A1 → 평가(10/24) → 동결(10/25 18:00).

## V — vision 탭 (OpenCV 5)
- [x] **V1** (3h) 환경·모델 선정·`VisionEngine` 골격(얼굴 검출+랜드마크+품질) + 모델 다운로드 스크립트
- [ ] **V2** (3h) ← V1 보정(5초 정면 baseline)과 지표(EAR·MAR·roll·face_scale·pitch 근사·어깨-귀), 이력 필터(안정화)
- [ ] **V2b** (2h) ← V2 `VisionEngine.analyze_variant`(enhance·zoom_face·strict) — 에이전트 능동 지각용(CONTRACTS §1) **+ `FrameResult.overlay`(정규화 얼굴 상자·랜드마크 점) 채우기**. A2가 가짜 vision으로 먼저 개발하므로 인터페이스만 맞추면 됨
- [ ] **V3** (4h) ← V2 동작 상태기계: T1 자리비움·갸우뚱·전방 머리, T2 깜빡임/깊은 깜빡임·하품, T3 음료(손 모델)
- [ ] **V4** (3h) ← V1 평가 하네스: 합성 변형 단위 테스트, 라벨 클립 포맷·`eval/record_clips.py`, 동작별 정밀도/재현율/지연 리포트
- [ ] **V5** (3h) ← V3 성능(프레임당 p95<250ms, 리사이즈·스레드), 강건성(무얼굴·다중 인물·역광·부분 가림), 품질 이슈 분류
- [ ] **V6** (2h) ← C4 COOL/arm64 백엔드 판별과 벤치용 `bench_vision.py`(동일 입력 반복 측정)
- 자율 라운드: 오탐 줄이기(시나리오별 실패 사례 수집), 코드 정리·docstring, 모델 라이선스 표 정리

## C — cloud 탭 (AWS)
- [~] **C1** (3h) 서비스 골격(FastAPI + Lambda 핸들러), 세션 상태 방식 결정·구현, 프레임 미저장 테스트, Dockerfile(arm64), vision/agent 미완성이어도 스텁으로 계약 응답
- [ ] **C2** (4h) ← C1 CloudFormation: S3+CloudFront(웹), ECR, Lambda 컨테이너(arm64)+Function URL, DynamoDB(TTL), 최소 권한 IAM, 로그 보존, 예산 알림, 배포·삭제 스크립트
- [ ] **C3** (2h) ← C2 captain us-east-1 첫 배포·스모크 테스트(`/healthz`, 세션·프레임 왕복)·엔드포인트 기록
- [ ] **C4** (3h) COOL 가능성 조사(Marketplace 리스팅 읽기 전용: 버전·요금·설치 방식) + x86(pip)/arm64 베이스라인 벤치 설계·실행 ← V1
- [ ] **C5** (3h) ← C3 관측성(EMF 지표: 프레임 지연·결정 수·오류, 대시보드), 비용·남용 방어(동시성 제한, 스로틀, 키 회전), 지연 최적화(콜드스타트)
- [ ] **C6** (2h) ← C5 재현 문서(`cloud/README.md`), 삭제 계획, 새 계정 기준 배포 검증
- 자율 라운드: 장애 주입(Lambda 타임아웃·DynamoDB 오류) 시 응답 확인, 보안 점검(키 로그 노출·CORS)
