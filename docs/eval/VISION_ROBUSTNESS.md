# 비전 견고성 리포트 (VISION_ROBUSTNESS)

실사용 왜곡(웹캠 JPEG 압축, 어두움/역광, 블러, 잡음, 해상도, 회전, 얼굴 크기, 부분
가림, 다중 얼굴)에서 엔진이 어디서 약한지 **측정으로** 드러낸 결과와, 그 근거로 한
구조적 보강이다.

> ⚠️ **정직성**: 입력은 **공개 OpenCV 샘플 4장 + 합성 변환**이다. 아래 수치는 실제
> 성능이 아니라 **구조적 약점 탐지·회귀 방지**용이다. 임계·규칙 조정의 근거는 이
> 합성 스윕에서만 나왔고, 실제 사용자 클립(U1)으로 재측정하기 전까지 일반화되지
> 않는다. 재현: `uv run python eval/robustness_sweep.py --out docs/eval/robustness`.
> 안경은 공개 안경 샘플이 없어 **미측정**(합성으로 흉내 내지 않음).

샘플: lena.jpg, messi5.jpg, largest_selfie.jpg, basketball1.png(군중 사진).

## 1. 조건별 요약 (보강 후)

`detect_rate` = 얼굴 검출률, `ear_delta` = 깨끗한 프레임 대비 EAR 변동(클수록 불안정),
`q_agree` = quality.ok 가 실제 검출(face_present)과 일치한 비율.

| 조건 | 대표 변형 | detect_rate | ear_delta | q_agree | 지연(ms) | 관찰 |
|---|---|---|---|---|---|---|
| JPEG 압축 | q90→q30 | 1.0 → 1.0 | 0.01 → 0.04 | 0.75 → 0.5 | ~12 | 검출은 견고, EAR는 q50↓에서 흔들림 |
| 밝기 | dark-80 | 1.0 | 0.05~0.07 | 0.5 | ~13 | 검출 유지, `too_dark` 정상 발생 |
| 감마 | g0.5 / g2.0 | 1.0 | 0.01~0.02 | 0.5 | ~12 | 안정 |
| 가우시안 블러 | gb7 / gb13 | 1.0 | 0.04~0.06 | 0.0 | 12~21 | 검출되지만 `blurry` 플래그(의도) |
| 모션 블러 | mb17 | 0.75 | 0.10 | 0.25 | ~15 | 강한 모션에서 검출 저하 |
| 잡음 | sp0.08 | 0.5 | 0.11 | 0.75 | ~11 | 소금후추 8%에서 검출 급락 |
| 해상도 | r160 / r320 / r640 | 0.75 / 1.0 / 1.0 | — | — | 5.6 / 9.5 / 25 | 160px에서 얼굴 과소, 640px 지연↑ |
| 회전 | rot10/20/30 | 1.0 / 0.75 / 1.0 | 0.08→0.16 | 0.75 | 12~18 | roll↑일수록 EAR 변동 큼(기울임 자체는 head_tilt로 포착) |
| 가림 | occ-mouth / occ-eye | 1.0 / 0.75 | 0.01~0.03 | 0.75 | ~13 | 눈 가림 시 검출 저하 |
| 얼굴 크기 | 60/30/15/8% | 1.0 / 0.5 / 0.0 / 0.0 | — | — | — | **프레임 15% 미만 얼굴은 검출 불가** |
| 다중 얼굴 | 뒤 사람 25/40% | persons=1 / 1 | — | — | — | **보강 후 주 얼굴 유지·오탐 없음** |
| 랜드마크 안정성 | 동일 프레임 반복 | — | std≈0.0px | — | — | 모델 결정론적(지터 없음) |
| 안경 | — | 미측정 | 미측정 | 미측정 | — | 공개 샘플 없음 |

## 2. 약점 상위 5개

1. **작은 얼굴**(프레임 ~15% 미만) 검출 불가. 멀리 앉으면 분석이 끊긴다 →
   `face_too_small` 로 사용자에게 "가까이 와 달라" 유도(아래 §4). 320×240 입력에서
   얼굴이 작아지기 쉬움.
2. **강한 블러/모션**(mb17, gb13): 검출은 되나 랜드마크·EAR 신뢰도 저하 → `blurry`
   플래그가 에이전트 재보정/second_look(enhance)로 연결되어야 함.
3. **잡음(소금후추 ≥8%)**: 검출률 0.5로 급락. 저조도 웹캠 노이즈에서 비슷할 수 있음.
4. **큰 회전(±20° 이상)**: EAR 변동이 커져(0.16) blink 판정이 불안정. roll 자체는
   `head_tilt` 로 올바르게 잡지만, 기울어진 상태의 눈 개폐 정확도는 낮다.
5. **군중/배경 얼굴**(보강 전): YuNet 저임계가 배경·질감을 얼굴로 집어 `multiple_faces`
   오탐이 거의 모든 프레임에 발생했다 → **§3에서 구조적으로 보강**.

## 3. 보강 (구조적, quality·얼굴 선택에 한정)

상태기계·모델은 건드리지 않았다. 근거는 §1 스윕(합성)이며 실제 클립으로 재측정 필요.

### (1) 주 얼굴 선택 규칙 — `select_primary_face`
- 기존: `faces[0]`(YuNet **점수** 1위) → 배경·작은 얼굴이 주피사체가 될 수 있었다.
- 변경: **가장 큰 얼굴, 동률(면적 10% 이내)이면 화면 중심에 가까운 얼굴**. 결정론적.
  `extract`(랜드마크)·`quality`(face_px)·`zoom_face`(variant)에 일관 적용.
- 효과: "뒤에 지나가는 사람"(구석의 작은 얼굴)이 분석을 가로채지 못함. 스윕에서
  bg-face 40% 케이스가 `primary_kept: true` 로 주 얼굴 유지.

### (2) `multiple_faces` 게이트 — `secondary_face_significant`
- 두 번째 얼굴이 주 얼굴 면적의 **40% 이상**일 때만 `multiple_faces`. 그 아래 작은
  배경/허위 검출은 플래그하지 않는다(`SECONDARY_MIN_AREA_RATIO=0.4`).
- 효과(스윕 전→후): 뒤 사람 40% 케이스 `persons 2→1`, `q_issues ["multiple_faces"]→[]`.
  단, basketball1(실제 군중 사진)처럼 **비슷한 크기 얼굴이 여럿**이면 여전히
  `multiple_faces`가 뜬다 — 이는 올바른 동작이다.

### (3) `face_px` 와 `persons` 가 주 얼굴 기준
- `face_px`(→`face_too_small`)는 주(최대) 얼굴 높이로 계산 → 배경 상자로 오판 안 함.
- `persons`는 주 얼굴 + 비슷한 크기 얼굴만 센다(`count_people`). 작은 배경 얼굴은
  카운트에 안 들어간다.

### 손대지 않은 것 (과튜닝 방지)
- `blurry`가 블러 프레임에 뜨는 것은 **정상**(에이전트가 "선명하게/밝게" 요청하도록
  연결). `q_agree=0.0`(gb7)은 "검출됐지만 품질 나쁨"을 뜻할 뿐 버그가 아니다 →
  임계 완화하지 않음.
- 밝기/블러/크기 임계값(`_DARK_BELOW`·`_BLUR_BELOW`·`_FACE_PX_MIN`)은 **변경하지
  않았다**. 합성 근거만으로 임계를 옮기면 실제 웹캠에서 어긋날 위험이 커서, 실제
  클립(U1) 확보 후 별도 작업으로 미룬다.

## 4. quality reasons → 에이전트 연결 확인

`quality.issues`(`too_dark`/`too_bright`/`blurry`/`no_face`/`multiple_faces`/
`face_too_small`)는 에이전트의 지각 입력이며, 아래로 이어진다(계약 §2, `agent/tools.py`):

- `get_quality` 도구가 issues 를 그대로 노출 → 결정 근거.
- 품질 불량·낮은 확신이면 `second_look(variant="enhance")`로 **같은 프레임을 다시
  보고**(CLAHE+감마), 해소되면 사람에게 묻지 않는다.
- 지속되면 `request_recalibration`(정면 5초) 또는 `ask_confirmation`(사람 확인).
- 사용자 안내 문구 예(관찰 기반, 진단 아님): "화면이 어두워요 — 조명을 밝혀 주세요",
  "얼굴이 작게 잡혀요 — 조금 가까이 와 주세요", "흔들려 보여요 — 잠시 가만히."

> 이 리포트의 보강은 quality reasons 가 **정확히** 뜨도록 만든 것이다(배경 얼굴로
> 인한 `multiple_faces` 오탐 제거). 실제 안내·재보정 동작은 에이전트 탭 소관이며,
> 여기서는 reasons 가 올바르게 생성되는지까지 확인했다.

## 6. V6 보강 — 기울어진 얼굴 EAR 보정 + 작은 얼굴 재시도

§2의 약점 중 2개(큰 회전에서 EAR 변동, 작은 얼굴 검출 저하)를 구조적으로 줄였다.
상태기계 임계·모델은 그대로다. 수치는 동일한 합성 스윕(공개 샘플 4장) 전후 비교이며
**실제 성능이 아니다**(실제 클립 U1로 재측정 필요).

### (a) roll-정렬 EAR — `metrics.roll_aligned_ear`
EAR 계산 전에 눈 6점을 머리 roll(이미 계산된 값)만큼 **역회전**해 눈을 이미지 축에
정렬한 뒤 종횡비를 잰다. baseline(보정값)도 같은 정렬 EAR로 저장한다. 새 모델/상태
없음. 좌표계만 바꿈.

- **직렬화 스키마 1.0 → 2.0.** baseline EAR 의미가 바뀌어 pre-V6 blob을 섞으면 안 되므로
  `SessionState.from_dict`가 `schema != "2.0"`를 **ValueError로 거부**한다(재보정 필요).
  신규 세션의 미직렬화 blob(스키마 없음)은 허용.

| 회전 | EAR 변동(전 V5) | EAR 변동(후 V6) |
|---|---|---|
| rot10 | 0.083 | **0.025** |
| rot20 | 0.100 | **0.050** |
| rot30 | 0.158 | **0.127** |

→ 세 각도 모두 변동 감소(특히 ±10~20°). 큰 회전(30°)은 여전히 남지만 개선됨.

### (b) 작은 얼굴 재시도 — `landmarks.extract_best`
full-res 추출에서 얼굴이 없거나 주 얼굴이 작으면(높이 ≤ 48px) **2배 업스케일 프레임에서
1회 재검출·재추출**하고 좌표를 원본 스케일로 되돌린다. analyze 내부 경로(variant 불필요).
더 큰 얼굴을 못 찾으면 원래 결과 유지. 아주 작으면 `face_too_small`이 우선.

| 얼굴 크기 | 검출률(전 V5) | 검출률(후 V6) |
|---|---|---|
| face~60% | 1.0 | 1.0 |
| face~30% | 0.5 | **1.0** |
| face~15% | 0.0 | **0.5** |
| face~8%  | 0.0 | 0.0 (너무 작음 → `face_too_small` 안내) |
| 해상도 r160 | 0.75 | **1.0** |

### 지연 (재측정)
- **일반 프레임**(재시도 미발생): analyze p95 ≈ 9.2ms — 회귀 없음(재시도는 작은
  얼굴/미검출에서만 발동).
- **작은 얼굴 프레임**(재시도 발동): p95 ≈ 13.6ms, **델타 +4.4ms** — 예산 +8ms 이내.
- 전부 계약 p95 < 250ms(Graviton, C 탭 측정) 대비 큰 여유.

> 이 §6 수치는 **V6 측정**(palm 경로 없음)으로, 작은 얼굴 재시도의 on/off 델타를
> 보이기 위한 것이다. V7에서 drink용 palm 경로(얼굴 있을 때 ≈ +2.7ms)가 추가되어
> **현재 파이프라인 전체 지연은 median ≈ 11.6ms / p95 ≈ 14.3ms**(320×240, VISION_EVAL
> §1). 재시도 델타(+4.4ms) 자체는 유효하다.

> 개선이 지연 예산을 넘으면 재시도 경로를 끄기로 했으나, +4.4ms로 예산 내라 유지한다.
> 두 보정 모두 개선이 수치로 확인되어 되돌리지 않는다. 합성 기준이며 실제 클립으로
> 일반화되지 않음은 §위 경고와 동일.
